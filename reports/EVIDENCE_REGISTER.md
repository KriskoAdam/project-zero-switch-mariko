# PROJECT_ZERO — evidence register

Status as of 10/30/2026. The register distinguishes the result on the physical user device from the host test, public documentation and model experiments. "Mariko relevant" does not mean that the SoC has been independently identified.

## Classification

- **A — physical console:** observation made on the user's console; it only applies to what the log directly records. The exact Mariko/T210B01 was not verified.
- **B — host + actual source:** secure host test of specific public source code. Does not apply to HOS unless the code is the same component.
- **C — public technical documentation:** the claim documents the listed public source, not automatically the target firmware.
- **D — analytical/model result:** applies to the analyzed model or derivation, not the original system.
- **E — hypothesis:** yet without reproducible target evidence.
- **F — refuted to the extent specified:** the result only refutes the specific wording/conditions of the test.

## Current summary

The most recent confirmations are PZ13-PHYS-01 (narrow physical captive-portal inventory) and PZ14-SMILE-01 (source check of author ns2jb's Switch 1 claim). PZ14 is not an independently reproduced technical find and the narrower Switch 1 claim was previously recorded in the project. No result is proof of Mariko's exploitability. The target Mariko SoC remains unverified and lacks a legitimate, credibly identified HOS executable/NPDM for static analysis.

### Open safe step

One physical check can compare the original captive-portal transition (HEAD 501 from our old server) with the patched server (HEAD 200), and see if the repeated HEAD requests stop. This measures the behavior of the test flow and does not detect vulnerabilities. Requires temporary start of local DNS/HTTP server and user return Switch DNS to Automatic. Expected result: the page loads and the log does not contain repeated HEAD 501. Stop condition: on connection/TLS cancel the warning and reset automatic DNS.
